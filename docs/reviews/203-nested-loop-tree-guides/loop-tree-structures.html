About these values

These values were saved when you evaluated the code. They are not live values. The variable after for shows its value at the start of each iteration. Other variables show their values when the body reaches its end.

Printed output shows what the program printed at that moment. If it prints u while u = 4, then sets u = 99, the row shows u = 99 beside printed 4. A value can carry over from an earlier iteration when the code does not assign it again.

Not recorded means there is no saved reading; it does not mean the variable was empty or the assignment did not run. Use Why? beside a missing value for its explanation. Evalens saves up to three body variable names per loop; the loop heading reports names left out.

Folding and paging browse saved results without running the code again. A loop reports when later iteration details or output were not saved. Those missing details cannot be expanded. An old result can also depend on changes Evalens could not detect; no warning is not a guarantee that it is current.

READING THE GUIDE

One inner loop, reached twice

The same for y loop runs once while x = 0, then again while x = 1.

for x in range(2)
├── for y in range(3)  x = 0
└── for y in range(3)  x = 1

My recommendation: F. Its branches lead directly to the two inner-loop headers. The gold iteration captions keep their results separate.

E shows every step in the tree.
F makes the loop-to-loop link the clearest.
G also marks the extent of each group of values.

These are proposals to choose between. No guide has been added to the extension.

All three keep one shared Variables / Printed output header, aligned values, the existing colors, and the same six recorded rows. No extra inner-loop expand button.
